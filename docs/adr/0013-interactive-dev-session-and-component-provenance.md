# Interactive Dev Session and Component Provenance

`@deckjsx/node` should grow an Interactive Dev Session for debugging generated artifacts through resident dev state, internal command/event dispatch, explain queries, history, and selection handles. This session remains an internal implementation detail of the Node dev runtime rather than a public WebDriver BiDi-compatible protocol; the public CLI may expose `--interactive`, but the command schema can evolve until the experience proves stable.

Component Provenance should be carried as dev-gated core metadata that can connect projected PPTX/PDF effects back to the function components that produced authored nodes. It is separate from Source Span, Media Source Origin, Render Execution Context, and Deck Plugin configuration: Source Span identifies a direct source location, Media Source Origin resolves local assets, Render Execution Context carries per-render integration state, and Deck Plugins remain author-configured pipeline participants. The initial provenance data should be limited to component name, module id, key, and source span so interactive inspection can explain ownership without retaining full props.

The transport should generalize the existing hidden metadata pattern behind `mediaSourceOrigins(...)` into an Authoring Metadata Carrier exposed through the Integration Interface. The carrier is generic as a transport, but its fields are a core-owned closed vocabulary rather than an arbitrary plugin payload bag; `mediaSourceOrigins` and `componentProvenance` are the initial fields.

Interactive diagnostics, cascade explanation, component inspection, and artifact history should be organized behind loosely coupled internal domains such as `session`, `diagnostics`, `component`, `style`, `projection`, `artifact`, `history`, and `selection`. `changes` should compare against the previous successful artifact update by default and report how many failed attempts were skipped between successful states.
