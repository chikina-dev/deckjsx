# PDF projection and runtime boundary

PDF output should be a first-class deckjsx output format with `pdf()` in the Adapter Interface and
`project({ format: "pdf" })` producing a PDF Page Model from the Semantic Author Graph. PDF must not
be generated by converting deckjsx's PPTX output, and core PDF Project/Render must remain
runtime-neutral enough for Edge-like runtimes: LibreOffice is a verification oracle for visual
fidelity, not a render-time dependency or measurement service. The PDF Page Model should stay close
to PDF document/page/resource/content-stream structure for writer speed, while sandbox-facing
explanations remain derived inspection views rather than a shared Presentation IR.
The model design should be specification-led: deckjsx should define an explicit PDF Specification
Profile from primary PDF and font references before building the first substantial writer surface,
so projected fields track PDF semantics instead of a temporary library API.

## Consequences

- `deckjsx/adapter` may expose `pdf()` beside `pptx()`.
- PDF implementation work should include a dedicated model research and fixture phase before broad
  visual-surface expansion.
- `@deckjsx/node write()` should write PDF rendered artifacts as ordinary artifact bytes, while
  retaining in-place patch behavior only for Patchable PPTX outputs.
- PDF visual regression should compare against deckjsx PPTX converted by LibreOffice, but this must
  stay in verification tooling.
