# v0.8.0 Public Surface Review

## Status

Release-candidate checklist item.

## Scope

This note classifies the public names changed by the v0.8.0 direct PPTX writer migration. It is the
release review artifact required by `docs/release.md`.

## Entry Points

- `deckjsx` is the Authoring Interface.
- `deckjsx/adapter` is the Adapter Interface.
- `deckjsx/inspect` is the Inspection Interface.
- `deckjsx/jsx-runtime` and `deckjsx/jsx-dev-runtime` are JSX runtime entry points.
- `deckjsx/package.json` is metadata.

No wildcard subpaths are exported. Writer internals, projection helper modules, validation modules,
runtime output modules, XML emitters, ZIP sinks, Assembly Plan builders, Build Artifact storage, and
fflate configuration are not public entry points.

## Authoring Interface

`deckjsx` exports authoring vocabulary: `Deck`, JSX authoring functions/elements, `Theme`,
`StyleSheet`, diagnostics, asset loader types, style/layout authoring types, template authoring
types, and stage result contracts needed by ordinary authoring code.

The root entry must not export detailed PPTX package types such as `PptxPackageModel`,
`PptxPackagePart`, PPTX drawing nodes, PPTX relationship payloads, PPTX theme payloads, generated
stroke layers, unsupported semantic records, or direct-writer helpers. These remain Inspection
Interface or internal Implementation vocabulary.

## Adapter Interface

`deckjsx/adapter` exports the direct PPTX writer selector `pptx()`, `PptxRenderOptions`,
`PptxCompressionMode`, and writer adapter result/context types. These are semantic adapter choices
and result DTOs, not writer storage.

The Adapter Interface may name `PptxPackageModel` only as the projection type consumed by a writer
adapter. It does not expose XML emitters, package-part bytes, media bytes, Asset Artifact storage,
Assembly Plan construction, ZIP sinks, fflate settings, or runtime filesystem output handles.

The historical `pptxgenjs()` adapter is removed from the core package. A future compatibility bridge
must live outside the core package.

## Inspection Interface

`deckjsx/inspect` exports read-only inspection vocabulary for Semantic Author Graph, resolved style
views, and Pptx Package Model snapshots. This includes package part ids, package part payload types,
relationships, PPTX drawing nodes, media metadata, theme projection traces, projected paint order,
unsupported semantic records, and project inspection summary/detail views.

`PptxPackagePartCandidate` is the structured candidate container for `defineProjection()` and future
sandbox workflows, so malformed package snapshots can be held long enough to produce diagnostics.
`PptxPackagePart` is the validated payload-bearing package part. Valid concrete parts are also
exposed through `PptxKnownPackagePart` and the specific part aliases such as `PptxMediaPart`,
`PptxSupportPart`, `PptxSlidePart`, `PptxRelationshipsPart`, and `PptxContentTypesPart`.

Callers should read broad package parts through the exported guards:

- `isPptxContentTypesPart()`
- `isPptxMediaPart()`
- `isPptxRelationshipsPart()`
- `isPptxSlidePart()`
- `isPptxSupportPart()`

`isPptxPackagePart()` narrows candidate parts to payload-bearing package parts. The concrete guards
then narrow valid broad package parts to specific payload shapes. This keeps malformed snapshot
diagnostics possible without asking users to write `as`, `Record<string, unknown>`, or
`as unknown as` in ordinary inspection code.

Stage results use the existing result-first contract rather than additional success flags:
`CompileResult`, `ProjectResult`, and `RenderResult` are unions whose artifact-bearing variants hold
`graph`, `projection`, or `artifact` respectively, while missing variants leave those properties
undefined. The corresponding `stages.*.artifact` status remains `available`, `partial`, or
`missing`, so diagnostics stay the source of truth and artifact presence expresses availability.

The local writer/project-render test fixtures follow the same rule for valid payload reads: they use
package-part guards and payload discriminants rather than broad `unknown` or object casts. Tests that
intentionally corrupt a snapshot keep the unsoundness on the broken field with `as never`.

Implementation code should also avoid broadening known pipeline values to `unknown`: Author Tree
children, graph props, rich text children, composition slide factory input, PPTX crop input,
text-transform input, and style declaration fallback values all have domain types and should use
those types directly.

## Type Boundary Evidence

- `tests/pptx/public-surface.test.ts` rejects generated public declarations that leak `unknown`,
  `Record<string, unknown>`, `readonly unknown[]`, writer modules, runtime modules, Build Artifacts,
  Asset Artifacts, XML writer types, ZIP sink types, or fflate vocabulary.
- `tests/types/jsx-public-api.tsx` rejects detailed PPTX inspection and direct-writer internals from
  the root Authoring Interface.
- `tests/types/adapter-public-api.ts` rejects PPTX inspection details from the Adapter Interface.
- `tests/types/inspect-public-api.tsx` proves `PptxPackagePartCandidate` values can be validated
  through public guards before reading payloads.
- `tests/types/jsx-public-api.tsx` proves public stage result variants keep artifact presence aligned
  with `stages.*.artifact` without adding parallel `ok` flags.

## Cast Policy

Implementation code may use `unknown` at actual runtime boundaries such as JSX input, exception
capture, user-defined projection snapshots, and asset loader results. That `unknown` should be
contained behind typed Module Interfaces.

Tests may use casts only to create intentionally malformed fixtures that normal public TypeScript
cannot construct. Tests should not use casts merely to read valid public results; when valid
inspection data needs narrowing, tests should use the public guards or exact exported part aliases.

## Release Decision

The v0.8.0 public surface is acceptable only if the generated declaration files remain free of
catch-all payloads and the root package continues to expose the direct PPTX writer as the default
render path without publishing writer internals or `pptxgenjs`.
