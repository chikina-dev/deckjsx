# v0.3.1 Graph Readiness Review

Status: Completed
Date: 2026-05-22

## Context

v0.3.0 introduced compile-first Graph Composition. Before adding Style Classes, Theme Support, and
Output Projection, v0.3.1 checks whether the codebase and Semantic Author Graph are understandable
from code and tests, and whether the graph has the right extension points for the next releases.

This is a review record, not an ADR. It records objective findings and the remediation performed in
v0.3.1.

## Review Method

1. Docs-blind codebase review:
   - Read `src/` and `tests/` first.
   - Infer the public API, graph model, composition boundary, diagnostics model, and output boundary
     from code and tests.
   - Record what is clear from code alone and what remains ambiguous.
2. Documentation cross-check:
   - Compare the code-derived understanding with `CONTEXT.md`, the roadmap, and ADRs.
   - Classify mismatches as terminology drift, missing docs, missing code structure, overbuilt code,
     or missing tests.
3. Remediation summary:
   - Record what v0.3.1 changed.
   - Defer remaining items to the release that should own them.

## Docs-Blind Findings

### Clear From Code

- `src/index.ts` presents `Deck`, JSX authoring components, diagnostics, and graph types as the main
  public surface.
- `Deck.compile()` is the graph-oriented entry point, while legacy `render()` and `output()` still
  flow through the current rendering path.
- `src/composition/` owns source composition before graph construction, and `src/graph/` owns
  Semantic Author Graph construction.
- `SemanticAuthorGraph` is clearly separated into `nodes`, `styles`, and `assets` maps.
- Diagnostics are structured and have category-specific error classes.
- Tests explain the intended composition behavior more clearly than the module names alone.

### Ambiguous From Code

- `StyleEntity.resolved` existed without a corresponding style resolution phase. That made it
  unclear whether resolved styles belonged inside the graph or in a later inspection/projection
  model.
- There was no graph-side place for authored class references, even though Style Entities are the
  natural insertion point for upcoming Style Classes.
- The absence of `className` in authoring props meant Style Class work would need to change both the
  authoring surface and the graph shape in the same later release.
- The output boundary is still easy to confuse with the legacy Presentation IR path because
  `render()` and `output()` remain present for compatibility.

### Boundary Risks

- If resolved concrete styles stay on `StyleEntity`, Output Projection may start depending on graph
  payload that should belong to a Resolved Style Inspection View or projection-local style resolver.
- If class references are not represented in the graph before v0.4, Style Class implementation may
  combine authoring prop design, graph shape changes, class lookup, diagnostics, and merge semantics
  into one larger change.
- If `className` is treated as a direct prop, Style Classes will mix with direct style overrides and
  become harder to reason about.

## Documentation Cross-Check

### Matches

- The code matches the documented direction that `compile()` is the primary inspection API and that
  Output Projection should consume the Semantic Author Graph.
- Composition resolution is separate from graph construction, which matches the documented
  `JSX -> Author Tree -> Graph Composition -> Semantic Author Graph` direction.
- Source Origin is present in graph origins, matching the v0.3 source-aware graph contract.

### Mismatches

- The roadmap previously placed Output Projection before Style Classes and Theme Support, but Style
  Classes and Themes strengthen Style Entities and should come before the output boundary.
- `StyleEntity.resolved` contradicted the glossary decision that resolved concrete style values
  belong to a Resolved Style Inspection View.

### Missing Tests

- Graph-shape tests were missing for class-only Style Entities.
- Type-level tests were missing for clsx-like `className` values and rejected numeric class tokens.
- Tests were missing to ensure `className` is excluded from authored direct props.

## Remediation

### Completed In v0.3.1

- Reordered the roadmap so Style Classes and Theme Support precede Output Projection.
- Added glossary terms for Style Class, Style Class Reference, Theme, and Resolved Style Inspection
  View.
- Removed `StyleEntity.resolved` from the graph type.
- Added `StyleClassRef` as `{ name, index }`.
- Added `StyleEntity.authored.classRefs`.
- Added clsx-like `className` authoring props to style-capable authoring nodes.
- Normalized `className` into ordered `classRefs` during graph construction.
- Kept `className` out of authored direct props.
- Kept `className` graph-only for v0.3.1; it does not affect legacy `render()` or `output()`.
- Added graph and type tests for class reference capture.

### Deferred To v0.4

- `defineStyles()` and Deck stylesheet registration.
- Style Class lookup.
- Missing class diagnostics.
- CSS-like class cascade semantics.
- Resolved Style Inspection View public shape for class-resolved styles.

### Deferred To v0.5

- Theme configuration shape.
- Theme token and component-default resolution.
- Theme application trace in Resolved Style Inspection View.

### Deferred To v0.6

- Output Projection and build/project/write API.
- Projection consumption of resolved style inspection output or projection-local style resolution.

## Outcome

The Semantic Author Graph is ready for v0.4 Style Classes once v0.3.1 lands. The graph now preserves
authored class references without resolving them, and resolved concrete style values are no longer
modeled as primary graph payload.
