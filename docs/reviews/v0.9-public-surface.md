# v0.9 Public Surface Review

This note classifies the public surface added for the v0.9 Patchable PPTX and Incremental Artifact
Runtime release. It is the release review artifact required by `docs/release.md` when exports
change.

## Root Package

`deckjsx/integration` is an Integration Interface, not root Authoring Interface. It exists so
Runtime Integration Packages can connect to core without importing internal source files or making
everyday deck authoring carry integration metadata.

The subpath exposes:

- `DeckPlugin`, `DeckIntegrationContext`, and `integrationContextId(...)` so integration packages can
  attach render-execution integration state through `deck.plugin(...)`.
- `withRenderExecutionContext(...)` and `RenderExecutionContext` so dev-time integrations can
  attach per-render Integration Context and source invalidation state without making it durable Deck Plugin
  configuration.
- `createIncrementalArtifactSession(...)`, `runIncrementalArtifactCycle(...)`,
  `getArtifactWriteToken(...)`, and `recordArtifactWrite(...)` so `@deckjsx/node` can coordinate
  render slots and write reporting without reaching into private pipeline artifacts.
  `runIncrementalArtifactCycle(...)` completes the cycle before resolving; runtime integrations
  should perform render and write reporting inside the callback rather than retaining write tokens
  for later use.
- `mediaSourceOrigins(...)` for integration transforms that attach prop-level Media Source Origin
  metadata.
- `createAuthoringExtensionValue(...)`, `isAuthoringExtensionValue(...)`, and the Authoring Extension
  Value / Authoring Lowering contracts so package-owned authoring values can be resolved by the
  matching Deck Plugin before graph construction.
- AssetLoader, Asset Source, Media Source Origin, Integration Context, and Render Patch Plan DTO
  types needed by integration packages.

The root `deckjsx` authoring entry does not expose these integration helpers as ordinary authoring
concepts. Root authoring remains focused on Deck, JSX authoring vocabulary, diagnostics, themes,
styles, templates, and result-first stage APIs.

`deckjsx/plugin-validation` is a narrow package-integration seam for shared Plugin validation and
stable same-id slot composition. It prevents Runtime Integration Packages from maintaining a
second interpretation of the Plugin contract while keeping validation utilities out of ordinary
root authoring.

`deckjsx/integration` must not expose direct writer storage, XML emitters, ZIP sinks, package-part
bytes, media bytes, or process cache handles. Render Patch Plan DTOs are metadata contracts for
Runtime Integration Packages; they do not expose build artifact storage or mutable writer internals.

## Integration Packages

`@deckjsx/node` is the Runtime Integration Package for Node file-system capabilities. It exposes
`write(await deck.render(pptx()), "out.pptx")`, Patchable PPTX inspection, and a Node local file
AssetLoader. It also exposes the `deckjsx dev` CLI through its package bin. It owns file locking,
in-place package patch writes, whole-archive rewrite fallback, Rolldown entry execution, file watch
coordination, and tracked-output filtering outside core.

Integration Context is render-execution scoped. Asset Entities keep Authored Media Source and Media
Source Origin metadata, but do not carry an owning Integration Context id. Project/Render resolve
assets through the root Deck Plugin stack for that execution.

The package publishes only `dist`, exposes only its root entry, CLI bin, and `package.json`, and
depends on core through a peer dependency. Published plugin manifests must contain no `file:../..`
dependency.

## Publish Checks

The v0.9 release workflow validates the selected package version against the release tag, checks and
packs the root package plus the Node integration package, and dry-runs or publishes only the
selected npm package.
Generated declarations are part of the public surface review: root and plugin package export maps
must include matching `types` and `import` targets.
